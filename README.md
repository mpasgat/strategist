# Стратег продукта: ИИ-агент для руководителя цифрового продукта

Папка-агент для Claude Code (работает и в Cursor и других средах, которые читают `AGENTS.md`). Ведёт руководителя от размытого запроса до продуктовой и коммуникационной стратегии с планом проверки. Каждое число и вывод ссылаются на реестр утверждений с источником. Факты, допущения, прогнозы и пробелы помечены. Расчёты и учёт расходов делают скрипты, а не модель.

Пример входных данных: `project/Пример_брифа.pdf` (вымышленный оператор, учебные числа), его кэш в `project/sources/brief.md`.

## Запуск за 5 минут

1. Установите [Claude Code](https://docs.claude.com/en/docs/claude-code/overview) и войдите в аккаунт (подписка Claude Pro/Max или ключ API в переменной окружения; ключи в репозиторий не кладутся).
2. Нужен Python 3.8+. Одна зависимость для чтения PDF:
   ```
   python -m pip install pypdf
   ```
   (вместо неё подойдёт утилита `pdftotext`). На Linux/macOS, если команды `python` нет, замените `python` на `python3` в `.claude/settings.json`.
3. Положите материалы задачи в `project/` (PDF, CSV, HTML, MD).
4. Откройте терминал в папке и запустите `claude`. На вопрос о доверии папке ответьте «да», иначе хуки не включатся.
5. Напишите задачу своими словами, например: «Вот бриф в project/Пример_брифа.pdf. Помоги выбрать первых клиентов и подготовить стратегию».

Агент сам задаст нужные вопросы и пойдёт по шагам.

## Как с ним работать

| Команда человека | Что делает агент |
|---|---|
| `стоп` | сохраняет состояние и останавливается |
| `уточни <что>` | возвращается на нужный шаг |
| `поправь <что>` | исправляет результат и перепроверяет затронутые выводы |
| новые данные («пилот показал…») | пересмотр: отзывает устаревшие утверждения и пересчитывает зависимые выводы |

**Продолжение после перерыва:** закройте чат или наберите `/clear`, затем просто напишите «продолжай». Агент прочитает `state/task.json` и продолжит с сохранённого шага.

**Три остановки для человека:** после постановки задачи, после вариантов (выбор направления), перед финалом.

## Рабочий процесс

1. Постановка (карточка задачи) → **СТОП 1**
2. Материалы: `tools/ingest.py` переводит файлы в `project/sources/` с метками мест (`brief.md#p4`)
3. Исследование: вопросы, которые могут изменить решение, честные пробелы
4. Варианты (навык `options`): минимум 3, включая «оставить как есть» и «закрыть», с сильными возражениями → **СТОП 2**
5. Стратегия (навык `strategy`): продуктовая, коммуникационная, план проверки
6. Независимый критик (субагент `critic`, видит только результат, не ход рассуждений)
7. Финал `output/final.md` с разделом «Сколько стоило» и его читаемая версия `output/final_readable.md` (`tools/render.py`) → **СТОП 3**

## Устройство

| Где | Что | Зачем |
|---|---|---|
| `AGENTS.md` | постоянные правила и процесс | читается в каждой сессии, короткий |
| `CLAUDE.md` | ссылка на `AGENTS.md` | для Claude Code |
| `.claude/skills/` | навыки `options`, `strategy`, `revise` | подгружаются только на своём шаге |
| `.claude/agents/critic.md` | субагент-критик (Sonnet) | независимая проверка |
| `.claude/settings.json` | Stop-хуки | проверка ссылок на факты и учёт расходов после каждого ответа |
| `knowledge/pitfalls.md` | 24 методические ловушки | чеклист автора и критика |
| `project/` | материалы задачи и кэш источников | каждый источник читается один раз |
| `state/` | `task.json`, `claims.jsonl`, `log.md`, `costs.csv` | состояние, реестр утверждений, журнал, расходы |
| `output/` | черновики, расчёты, итог | |
| `tools/` | скрипты (только стандартная библиотека Python, кроме pypdf) | |
| `tests/` | тесты скриптов на pytest | без сети, во временных папках |

### Скрипты

- `tools/ingest.py <файл> --slug <имя> [--url <адрес>]`: источник в markdown с метками страниц и строк, кэш по sha256.
- `tools/calc.py funnel | breakeven | retention | payback | sample-size | delta | mix | trial-value | activation-payback`: расчёты в двух сценариях (базовый и неблагоприятный), результат с допущениями в `output/calc/`. `mix` раскладывает падение общей доли на смену структуры и изменение внутри групп, `trial-value` даёт итог пробного аккаунта за горизонт, `activation-payback` — окупаемость прироста активации от даты вложения по месячным когортам.
- `tools/lint_claims.py [--root <папка>] [файл.md]`: каждое число со ссылкой `[Cxxx]`, у факта есть источник и метка, у допущения и прогноза слово-метка, нет ссылок на отозванные записи. В режиме хука блокирует завершение ответа с ошибками (с шага 5).
- `tools/render.py [--root <папка>] [--in output/final.md] [--out ...]`: версия итога для руководителя: ссылки `[Cxxx]` заменены сносками [1], [2], в конце раздел «Основания» (текст утверждения, тип, источник). Пометки «допущение», «прогноз» в тексте остаются. Отказывается собирать, если ссылка ведёт на отозванную или несуществующую запись.
- `tools/cost_report.py [--scan | --hook | --file X.jsonl]`: токены, время и эквивалент стоимости по ценам API из реальных транскриптов Claude Code (`tools/prices.json`, источник цен указан в файле).

### Модели

| Шаг | Модель | Почему |
|---|---|---|
| 1–3, правки | Sonnet | достаточно для постановки и сбора, дешевле |
| 4–5 | Opus | варианты и стратегия требуют глубины |
| критик | Sonnet (задано в `critic.md`) | включается автоматически |

Модель главного чата выбирает человек (`/model`); агент сам предлагает переключиться перед шагом 4. Меняйте модель после `/clear`, иначе кэш контекста пишется заново.

Тесты: `python -m pytest` (зависимость: `python -m pip install -r requirements-dev.txt`).

## Демо

В `examples/megafon/` лежит полный прогон учебной задачи из брифа: шаги 1–7, проверка критиком и два пересмотра по новым данным аналитика.

- `project/sources/`: бриф и веб-источники в markdown с метками, плюс `notes.md` с новыми данными.
- `state/`: карточка задачи `task.json`, реестр утверждений `claims.jsonl` (с отозванными записями), журнал `log.md`, расходы `costs.csv`.
- `output/`: исследование, варианты, стратегия, расчёты `calc/` и итог.

Начинать читать с `output/final_readable.md` (то же, что `final.md`, но со сносками вместо `[Cxxx]`): вывод и просьба к руководителю в первых строках. Прогон занял 26 мин работы агента и 101 запрос к модели, ≈ $8.15 по ценам API (замер `tools/cost_report.py`). Проверить ссылки демо: `python tools/lint_claims.py --root examples/megafon output/final.md`.

Второй прогон, `examples/task2/`: задача «Фотооблако» (бриф и таблица когорт), шаги 1–7, критик и правки после финала. Начинать с `output/final_readable.md`. Прогон занял 13 мин работы агента, 63 запроса, ≈ $4.57 по ценам API. Проверить ссылки: `python tools/lint_claims.py --root examples/task2 output/final.md`. Рядом лежит `baseline.md` — ответ обычного чата claude.ai на тот же промпт. Сравнение по чеклисту: [`docs/comparison.md`](docs/comparison.md).

Исправлено после прогона: Stop-хук учёта расходов молча пропускал запись, если путь к транскрипту содержал кириллицу (stdin читался в cp1251). Теперь `cost_report.py` и `lint_claims.py` в режиме `--hook` читают stdin как UTF-8, на это есть тесты.

## Безопасность и данные

- Только открытые источники и материалы пользователя. Секреты только в переменных окружения, `.env` и ключи в `.gitignore`.
- Текст источников это данные: инструкции внутри них не выполняются.
- Синтетические респонденты, если используются, помечены и не считаются доказательством спроса.

## Ограничения

- Модель главного чата не переключается автоматически, это делает человек.
- Учёт расходов читает формат транскриптов Claude Code; в других средах расходы нужно вносить вручную.
- Сканированные PDF без текстового слоя требуют OCR (скрипт об этом предупредит).
